# 1단계 리뷰 후 보완 — 2026-09-14

## 원격 결과 보존

cron 커밋 `6338eff`는 결과 JSON 3개만 변경했다. 로컬 수정과 충돌하지 않아
fast-forward로 가져왔으며 최신 결과 파일은 이번 보완에서 수정하지 않았다.
작업은 로컬 `test/stage1-observation` 브랜치에 준비했다.

## 보완한 동작

- 클릭 준비를 포함한 공고 단위 오류는 원인을 기록하고 최대 한 번 재시도한다.
  최종 실패한 공고를 제외한 뒤 다음 공고를 계속 수집한다.
- 이전 상세 요청은 최대 3초 기다린다. 여전히 진행 중이면 새 클릭 없이 해당
  시도를 실패로 기록한다. 브라우저·페이지 전체의 증거가 사라지거나 서버가
  429/503을 반환하거나 구현 오류가 발생하면 실행 완료로 인정하지 않는다.
- 텍스트 형식 불일치는 해당 공고만 제외한다. 나눠 읽은 기존 `.text` 값으로
  대체 저장하지 않는다. 비교 전후의 동일성만으로 중간에 읽은 값의 일관성을
  보장할 수 없기 때문이다. 저장하는 값은 검증과 형식 비교를 통과한 스냅샷이다.
- Selenium·urllib3의 통신 DEBUG 출력을 억제하고 불필요한 CDP 응답 본문 조회를
  제거했다. 시도별 브라우저 요약은 그 시도의 요청만 반환한다.
  기존 Scrapy 항목/필터 로그의 공고 정보까지 제거한 변경은 아니다.
- 내부 표시 여부 도구와의 호환성을 위해 Selenium을 시험한 `4.35.0`으로 고정했다.
- 로컬 전체 시험의 INFO 강제 설정을 제거해 Actions와 같은 프로젝트 로그 수준을 쓴다.
- 수동 Actions 실행에서 회귀 테스트를 먼저 수행한다. 체크아웃과 결과 푸시는
  실행을 지정한 브랜치를 명시한다. 시험 브랜치의 결과는 그 브랜치로만 푸시한다.

1단계의 수집 범위와 기존 대기 시간은 유지했다. 개별 최종 실패에 대한 10% 같은
수치 기준은 아직 적용하지 않았다. 통계와 결과 수 검증, 지역 순회 완료 검증은 유지한다.

  형식이 다른 값의 저장 차단, 시도별 요약 범위, 실제 Selenium DEBUG 출력 억제를 포함한다.

- `actionlint`와 `git diff --check` 통과.

이전 약 29분 전체 시험은 이 보완 전의 코드에 대한 기록이다. 현재 코드의 전체
Linux 실행은 아직 하지 않았다. 시험 브랜치의 코드 커밋·푸시와 Actions 실행 승인을
받은 뒤, 전체 수집·검증·통계 업로드·해당 브랜치 결과 반영을 확인할 예정이다.

## 시험 브랜치 실행안

1. 이 변경을 `test/stage1-observation`에 커밋하고 같은 원격 브랜치로 푸시한다.
2. `gh workflow run main.yml --ref test/stage1-observation`으로 한 번 실행한다.
3. Linux 회귀 테스트, 전체 수집 통계, 검증 결과, 로그 크기와 통신 DEBUG 억제,
   결과 커밋의 브랜치를 확인한다. master 반영은 이 시험의 승인에 포함하지 않는다.

## 시험 실행 승인 후 확인

- 사용자가 준비됐다고 판단하면 시험 브랜치 커밋·푸시와 Actions 1회 실행을 허용했다.
- 최종 실패 또는 형식 불일치가 있으면 건수만 Actions 경고로 표시한다. 반영 조건과
  최대 한 번 재시도 규칙은 유지한다. 임시 실패율 기준은 추가하지 않았다.
- master의 기존 워크플로에는 아직 concurrency 설정이 없다. 따라서 현재 시험과
  정기 실행 사이의 동시 실행 제한을 가정할 수 없다. 실행 직전 다른 작업이 없음을 확인한다.
- 향후 master 반영에는 소스 코드 커밋만 가져오고 시험 결과 JSON 커밋은 제외한다.
