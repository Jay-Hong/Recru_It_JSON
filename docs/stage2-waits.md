# 2단계 첫 변경: 종료·지역 시작 대기 축소

사용자 요청에 따라 실제 시간 단축을 시작하고 수동 Actions 시험 1회로 확인한다.
비교 기준은 master 1단계 수동 실행 `34797933409`다. 해당 실행은 전체 31분 18초,
수집 30분 33초, 대상 465건 모두 검증, 저장 319건이었다.

## 변경

- 지역 시작 대기는 첫 번째 수집 대상 직전에 한 번만 수행한다.
- 모든 지역의 `sleep_before`를 `(1, 4)`로 설정하고 연속 균등분포로 뽑는다.
- 수집 대상이 없는 지역은 시작 스크롤과 대기를 생략한다. 수동 공고와 지역 완료 기록은 유지한다.
- 종료 직전 3~30초 대기를 제거한다. `final_wait`가 기록에 없으면 이 단계에서는 0초다.

기존 대상 선정 조건과 순서를 그대로 사용한다. 전체 목록 순번 제한, 간편지원 제외,
지역 포함·제외 조건을 통과한 첫 카드에서 지역을 시작하므로 별도 후보 목록을 만들지 않는다.
대상이 있는 지역의 기존 시작 스크롤 위치는 유지한다.

클릭 전 대기, 클릭 후 0.5초 경과 조건, 준비 확인, 텍스트 비교, 재시도, 초기 페이지 대기,
스크롤 횟수·대기는 이번 변경에서 유지한다. 급여 사전 필터와 User-Agent 변경은 포함하지 않는다.

## 기대 효과와 비교 방법

직전 수동 실행의 지역 대기는 127.002초, 종료 대기는 19.000초였다.
대상이 있는 지역 16곳에 평균 2.5초를 대입하면 지역 대기 40초로, 약 106초(5.6%) 절감을 예상한다.
이는 같은 실행에 새 설정을 대입한 모델이다. 새 실행의 전체 시간이 106초 줄어든다는 보장은 아니다.

실제 시험에서는 다음을 비교한다.

1. `region_wait` 합계와 대상이 있는 지역 수, `final_wait` 제거 여부.
2. 대상·스크롤·목록 수와 최초/재시도 시간. 하위 타이머를 다시 더하지 않는다.
3. 검증 성공·최종 실패·가림 복구·형식 불일치·지역 완료·필터 제외 사유.
4. 상세 POST/OPTIONS 수, 응답 지연, 사이트 요청의 움직이는 60초 최대치와 429·503.

지역 대기를 줄이면 서로 다른 지역의 요청이 같은 60초 구간에 더 많이 들어갈 수 있다.
지역 전환이 17번뿐이라는 이유로 요청 밀도에 영향이 없다고 단정하지 않는다.
수동 시험과 정기 실행은 기록을 구분하며 시간대에 따른 장기 변동은 정기 기록으로 보완한다.

## 검증과 반영

- 합성 회귀 테스트는 후보 순서·전체 순번 제한·제외 조건, 빈 지역, 수동 공고, 기존 클릭 대기와
  완료 동작을 확인한다. 기존 공고 확인·실패 복구 테스트도 함께 실행한다.
- 집계 도구는 `--cohort stage2-waits=<코드커밋SHA>`로 새 단계를 등록해 이전 기록과 나눠 표시한다.
  알 수 없는 코드 버전을 자동으로 같은 단계로 인정하지 않는다.
- 수동 시험은 `test/stage2-waits` 브랜치에서 실행한다. 결과 자동 커밋도 그 브랜치로 향한다.
  master 반영 시 시험 결과 JSON 커밋을 가져오지 않도록 코드 커밋과 구분한다.

## Claude 검토에서 바로잡은 해석

- 직전 master 수동 실행의 초기 페이지 대기는 10초가 아니라 7초다. 10초는 앞선 시험 브랜치 실행 값이다.
- 준비 시간이 0.5초를 넘은 6건은 검증 성공까지 확인된다. 최종 저장 여부는 이후 필터와 별개다.
- 시간대별 가림 차이는 가능한 가설이다. 표본의 날짜·공고·러너·무작위 화면 크기가 통제되지 않았으므로
  낮에 서버가 더 바쁘거나 시간대가 가림의 원인이라고 확정할 수 없다.
- 종료 대기는 수집 루프가 끝난 뒤지만, 이것이 브라우저의 모든 백그라운드 요청 완료를 뜻하지는 않는다.
  저장에 필요한 값은 이미 검증된 스냅샷에 확보된 상태이므로 종료 대기 제거의 근거가 된다.
