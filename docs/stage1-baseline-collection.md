# 정기 실행 기준선 수집

2026-09-15 현재는 목록 보완 코드 `57e8d4b`의 정기 실행 3~5회를 모은다.
수동 시험 `34911124421`은 참고 자료이며 정기 실행 횟수에 포함하지 않는다.
아래 1단계 기록은 과거 이력으로 보존한다. 유지보수 등으로 운영 코드·의존성·워크플로가
바뀌면 새 코드 SHA를 별도 `--cohort`로 등록하고, 이전 단계와 같은 기준선으로 합치지 않는다.

## 실행 방법

저장소 루트에서 다음 명령을 실행한다. Python 표준 라이브러리와 로그인된 `gh`, `git`이 필요하다.

```sh
python3 -B scripts/collect_stage1_baseline.py \
  --output "$HOME/Documents/Recru_It_JSON_measurements/regular-runs" \
  --cohort list-settling=57e8d4b82e2b5343bfb7af78e2273a0bdccf6bb2 \
  --reference-run 34911124421
```

새 단계의 코드가 커밋되면 `--cohort stage2-waits=<코드커밋SHA>`를 추가한다.
도구는 `stage1`과 명시적으로 등록한 코드의 Git 객체를 각각 대조하고 단계별로 표시한다.
반복 비교에는 움직이는 브랜치 이름보다 확정된 코드 커밋 SHA를 사용한다.
수동 시험은 `--reference-run <실행ID>`로 추가하면 단계 이름과 함께 참고 행으로 표시된다.

- `main.yml`의 master 정기 실행 중 2026-09-14 이후 기록을 조회한다. 다른 워크플로나
  의존성 정보 갱신 작업은 포함하지 않는다. 조회 기간은 `--since YYYY-MM-DD`로 지정한다.
- 실행 ID와 시도 번호별로 실행 정보, 작업 시간, 원본 통계, artifact ID·만료일·SHA-256을 보관한다.
  보관 경로는 저장소 밖이어야 한다. 전체 로그·결과 JSON·응답 본문은 내려받지 않는다.
- 원본 통계는 재실행해도 덮어쓰지 않고 해시를 확인해 재사용한다. GitHub artifact가
  만료된 뒤에도 내려받은 통계는 남는다. 새 통계는 만료 전에 이 명령을 실행해야 보관된다.
- `summary.md`와 `summary.json`은 조회할 때 갱신된다. 실패·진행 중·통계 누락·만료 실행도
  표에 남긴다. GitHub API 조회 자체가 실패하면 오류로 종료하며 기존 보고서를 최신으로 표시하지 않는다.
- 이 명령은 GitHub 읽기와 `git fetch`만 수행한다. 크롤러 실행, workflow dispatch,
  결과 반영, 브랜치 변경, commit/push, 자동 감시는 수행하지 않는다.
- 정기 실행이 끝난 뒤 다시 실행해야 새 기록이 보관된다. 이 문서나 명령 준비만으로
  향후 실행 검토가 자동 예약되지는 않는다. 통계 artifact는 14일 안에 보관한다.

## 비교 기준

비교 가능한 정기 실행은 첫 시도가 성공했고 통계 ID·완료 표시·지역별 집계가 맞으며,
진단 누락이나 전체 수집 오류가 없는 실행이다. 재실행은 별도로 표시하고 기본 횟수에는 넣지 않는다.
운영 코드·설정·의존성과 워크플로의 Git 객체가 `34ad3b1` 또는 등록한 단계의 코드와 같은지도 확인한다.
결과 JSON이나 문서 커밋 때문에 기준선이 나뉘지는 않는다.
등록하지 않은 코드 변경은 자동으로 허용하지 않는다. 알려진 단계여도 서로 다른 단계의
실행을 하나의 기준선으로 합치지 않는다. 클릭 구간 지표의 비교도 무작위 대기·대상 구성·
재시도 수·시간대의 영향을 함께 검토한다.

부분 공고 실패가 있으면 횟수에 포함하되 검토 사항으로 남긴다. 3회가 쌓였다는 이유만으로
다음 단계를 자동 승인하지 않으며, 다음 항목을 함께 본다.

1. 작업 시간과 수집 단계 시간, 대상 수, 스크롤 수, 목록 수.
2. 최초·재시도 전체 시간을 대상 수로 나눈 값과 스크롤 1회당 시간.
   최초·재시도 시간에는 클릭 대기·검증·텍스트 비교가 들어 있으므로 다시 더하지 않는다.
3. 상세 POST 응답 시간과 화면 준비 시간의 표본 수·중앙값·95백분위·최대.
   95백분위는 기존 보고서와 같이 정렬한 값의 `floor((n-1)*0.95)` 위치를 쓴다.
   응답 지연에는 수집 중 상세 POST만 포함한다. 준비 시간은 최종 검증에 성공한 시도의
   브라우저 클릭 기준 관측치이며, 두 분포의 표본 수는 다를 수 있다.
4. 실제 요청 수와 OPTIONS 비중, 움직이는 60초 최대치, 상태 코드별 집계.
   시간대가 다른 분류별 최대치를 더해 사이트 전체 최대치로 사용하지 않는다.
5. 가림·재시도·최종 실패·형식 불일치·진단 누락, 지역별 완료와 검증/저장/제외 분포.
   저장 0건과 읽기 실패를 구분하고, 실패한 날도 함께 검토한다.

통계 점검은 원본 결과 JSON을 다시 검증하는 작업이 아니다. 결과 반영 성공은 Actions의
수집·검증·커밋·푸시를 포함한 작업 결과로 확인한다. 집계 도구 자체는 실패율 기준이나 운영 설정을 바꾸지 않는다.
