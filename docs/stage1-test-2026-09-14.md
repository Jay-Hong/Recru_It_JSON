클릭과 연결된 상세 요청 457건 전부에 네트워크 요청 ID가 연결됐다.
이 요청들은 응답 본문 확보도 모두 성공했다. 화면 준비 시간과 네트워크 시간은
각각 페이지 시계와 CDP 시계 내부에서 계산했다.

수집 구간에서 관측한 요청은 목록 관련 82회, 상세 관련 676회, 같은 사이트의
기타 요청 155회였다. 사이트 요청 전체의 움직이는 60초 최대치는 64회였다.
관측된 사이트 응답은 모두 200이고 429·503은 없었다.
이 수치는 브라우저에서 관측한 통신이며 서버 내부 처리량을 뜻하지 않는다.

클릭 457회와 상세 관련 요청 676회는 같은 지표가 아니다. 추가 소규모 측정에서
상세·목록 POST 외에 OPTIONS 사전 확인 요청이 실제로 발생함을 확인했다.
따라서 이후 속도 조정은 클릭 수뿐 아니라 실제 요청 수와 지연도 비교해야 한다.

전체 실행 기록에는 공고 클릭과 연결되지 않은 요청의 본문 확보 실패가 220건 있었다.
추가 표본에서는 OPTIONS 본문 조회가 같은 진단 오류를 만들었다. 전체 실행 당시에는
HTTP 메서드를 보관하지 않았으므로 220건 전부를 OPTIONS라고 확정하지는 않는다.

전체 수집 후 **진단 처리만** 보완했다. HTTP 메서드·리소스 종류를 기록하고 OPTIONS는
요청 수에 포함하되 상세 본문 조회에서는 제외했다. 이 보완 후 실제 공고 2건을
재검증해 공고 확인·요청 연결 모두 통과했고 진단 오류는 0건이었다.
전체 수집의 29분 11초는 이 마지막 진단 보완 전 코드에서 측정한 값이다.

기존 대기 합계는 초기 9.01초, 스크롤 224.48초, 지역 사이 98.16초,
클릭 전 1,060.71초, 클릭 후 232.09초, 종료 전 8.01초였다.
검증 호출은 총 3.93초, 기존 텍스트 비교는 47.88초였다.
재시도 구간 38.14초에는 해당 대기·검증·비교가 포함되므로 다시 더하지 않는다.
