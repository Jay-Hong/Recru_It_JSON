# 급여 사전 필터·클릭·스크롤 간격 묶음 시험

사용자 요청: 스크롤 간격 단축까지 함께 구현하고 전체 Actions 시험 한 번으로 평가한다.
master 반영은 시험 결과를 검토한 뒤 별도 승인 대상으로 남긴다.
기준 실행은 대기 축소 버전 `34810465315`(전체 29분 19초)이며,
원래 크롤러의 10회 평균 28분 36초와도 구분해 보고한다.

## 구현과 스위치

`recru_it/recru_it/settings.py`의 `CRAWL_CONFIG['optimizations']`에서 각 변경을 끈다.

- `salary_prefilter`: 일급(`priceDiv=1`)·월급(`3`)만 대상으로 한다. 카드의 숫자 금액이
  100,000 이상 150,000 미만이고 목록의 표시 금액과 일치할 때만 제외 후보가 된다.
  주급·협의·불명확한 단위/숫자/범위·서로 다른 금액은 기존대로 상세 수집한다.
  100만~149만원 등 기존 필터가 추가로 제외하는 금액은 사전 제외 범위에 포함하지 않는다.
- 첫 제외 후보는 반드시 상세를 읽고, 나머지는 `salary_audit_rate=0.2` 확률로 읽는다.
  따라서 실제 표본 비율은 정확히 20%가 아니다. 검증된 상세를 기존 정리 규칙으로 변환한
  급여가 기존 일급/월급 제외 정규식에 맞는지 확인한다. 표본은 정상 파이프라인으로 보낸다.
  불일치는 실행 중단, 표본 확인 실패는 결과 반영 차단 대상이다.
  과거 일치와 이번 표본 일치는 건너뛴 모든 공고의 정답을 보장하지 않는다.
- `click_interval=(1.6, 2.8)`: WebDriver 클릭 명령의 시작 간격을 연속 균등분포로 정한다.
  확인·필터·지역 대기·재시도 준비 시간이 간격에 포함된다. 늦었을 때 밀린 클릭을 보내지 않는다.
  가림으로 실제 요청이 나가지 않은 클릭 시도도 같은 간격을 사용한다. 준비 확인과 기존 텍스트
  비교는 유지하고 클릭 후 고정 0.5초만 제거한다. `None`이면 기존 지역별 대기와 0.5초로 복귀한다.
  명령 시작 간격과 실제 DOM 클릭/네트워크 요청 간격은 다를 수 있어 각각 기록으로 비교한다.
- `scroll_interval=(1.5, 2.5)`: 스크롤 명령 시작 간격과 새 목록 준비를 모두 충족한다.
  응답 진행 상태·사이트의 로딩 상태·화면/모델의 목록 수를 함께 확인한다. 첫 스크롤에서
  요청 없이 목록 수가 같은 현상은 2.5초 이상 관찰한 뒤 준비 동작으로 허용한다.
  이후에는 목록 증가 또는 직접 관측한 `recuit_pageload=complete` 이벤트가 필요하다.
  확인이 늦으면 5초 관찰 후 한 번 더 5초 관찰하며, 추가 스크롤 요청은 보내지 않는다.
  끝내 확인되지 않으면 수집 완료로 처리하지 않는다. `None`이면 기존 스크롤 루프로 복귀한다.

## 이동 준비 확인 보완 시험

사용자 승인에 따라 동일 시험 브랜치에서 구현하고 Actions 전체 시험을 1회 진행한다.
master 반영은 이 시험 범위에 포함하지 않는다.

- `scroll_range=(54, 58)`로 기존 평균 수집량에 가깝게 보정한다. 스크롤 간격은
  1.5~2.5초 그대로다. 첫 목록 15개·첫 스크롤 증가 0·이후 15개씩이라는 패턴이면
  810~870개가 되지만 보장된 개수는 아니다. 명시적 목록 끝은 먼저 종료한다.
- 지역의 첫 실제 조회 대상에 먼저 이동하고 기존 1~4초 지역 대기를 둔다.
  공통 앞 위치를 경유하거나 대기 직후 다시 스크롤하지 않는다. 사전 제외만 있는
  지역에는 이동·지역 대기가 없다. 재시도도 해당 대상에만 이동한다.
- `click_readiness`는 이동 전에 브라우저 프레임 관측을 시작한다. 대상의 위치·크기와
  조상 스크롤 위치가 0.2초 동안 안정되고, WebDriver의 화면 안 클릭 중심점을 실제
  대상 또는 자식이 차지해야 한다. 100ms 넘게 관측이 끊기면 안정 구간을 다시 센다.
  클릭 간격 대기 뒤에도 준비되지 않으면 최대 5초 추가 확인하고, 클릭하지 않은 채
  `click_not_ready`로 기록해 기존 1회 재시도 경로를 따른다. 강제 JS 클릭은 쓰지 않는다.
- 이동 관측은 지역·클릭 간격 대기 중에도 진행된다. 다음 클릭 간격의 기준 시각은
  추가 확인까지 끝난 실제 클릭 명령 직전이므로 밀린 클릭을 연속해서 보내지 않는다.
- 시도별 `region_first_candidate`, `click_readiness`(안정 시간·이동 후 경과·좌표 변화·
  가림 관측 횟수·클릭 좌표), `click_ready_wait_seconds`를 남긴다. 연락처·본문·요소 HTML은
  남기지 않는다. 수집한 공고에는 준비 확인 증거가 있어야 결과 검증을 통과한다.
- `click_readiness_check`는 추가 확인 구간, `click_ready_poll`은 그 안의 대기다.
  브라우저의 `elapsed_seconds`는 지역·클릭 대기와 겹치므로 별도 절감/추가 시간으로
  더하지 않는다. `first_attempt`/`retry`에서는 지역 대기를 빼 이전 타이머 범위를 유지한다.

기존 지역별 전체 목록 순번 제한·대상 선정 순서는 유지한다.
초기 페이지 대기, User-Agent, 결과 JSON 형식과 기존 후처리 규칙은 이번 변경 범위 밖이다.

## 한 번의 시험에서 확인할 것

- 설정값, 전체/수집 시간, 스크롤 및 최초/재시도 구간 시간. 포함 관계인 타이머를 다시 더하지 않는다.
- 대상 = 사전 제외 + 검증 + 최종 실패, 검증 + 수동 = 저장 + 파이프라인 제외.
- 사전 제외 후보·제외·표본 선택·검증·불일치·확인 실패 건수. 표본 불일치/미확인은 0이어야 한다.
- 계획한 스크롤 완료 또는 실제 끝 신호, 목록 수, 지역 완료 상태, 형식 비교 결과.
- 목록/상세 POST 및 OPTIONS, 기타 사이트 요청, 응답 지연 분포, 움직이는 60초 최대 요청 수.
  요청 최대 구간의 위치와 자원 종류도 확인한다. 요청 수만으로 서버 처리 비용을 단정하지 않는다.
- 429/503 관측 시 기존처럼 실행을 중단한다. 최종 실패는 직전 두 시험의 0~1건과 비교하고,
  상세 응답 p95는 직전 약 0.456초와 비교한다. '크게 늘지 않음'을 자동 통과 기준으로 쓰지 않는다.
  새로운 실패·형식 불일치, 지연 증가, 요청 밀도가 보이면 원인과 수치를 검토한 뒤 반영을 판단한다.

전체 시간 예상은 약 20~22분이며 실측이 아니다. 표본 조회는 절감량을 줄이고 재시도·로딩·목록 수는
전체 시간을 바꾼다. 한 번의 성공으로 다른 시간대의 서버 상태나 장기 안정성을 입증할 수 없다.
이번 시험 통계는 별도 코드 묶음으로 보관한다. 집계 도구도 사전 제외와 실제 조회 대상당 시간을
구분하므로, 사전 제외를 정상적으로 처리한 실행이 건수 불일치로 잘못 표시되지 않는다.
