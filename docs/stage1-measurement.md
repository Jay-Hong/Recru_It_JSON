# 1단계: 수집 검증과 측정

1단계는 기존 수집 범위와 모든 임의 대기, 클릭 후 0.5초를 유지한다.
속도 설정 변경과 급여 사전 제외는 다음 단계다. 클릭 가림 재시도와
기존 텍스트 비교 때문에 이번 단계의 실행 시간은 늘어날 수 있다.

## 저장 조건

- 목록 카드의 Vue 렌더 키에서 해당 공고 ID를 찾는다.
- 클릭 전에 시도 번호와 직전 상세 객체를 기록한다. 실제 DOM 클릭 이벤트를
  시작 시점으로 삼고, 이전 상세 요청이 진행 중이면 새 시도를 시작하지 않는다.
- 상세 객체가 새 객체로 교체되고 ID가 일치해야 한다. 제목이 같아도 허용한다.
- 제목·지역·직종·급여·조건·인원·연락처·본문·이미지 주소를 모델과 대조한다.
  데이터와 화면을 같은 JavaScript 호출 안에서 읽고, 검증한 스냅샷을 저장한다.
- 현재 사이트의 DOM에서 블록 경계와 텍스트 노드 내부의 줄바꿈을 구분해
  기존 WebDriver의 공백 처리를 보존한다. 기존 `.text`와 모든 필드를 비교한 뒤
  화면이 그대로인지 다시 확인한다. 값이 바뀌거나 형식이 다르면 해당 공고를 재시도하며,
  끝내 일치하지 않으면 그 공고를 제외하고 원인과 건수를 기록한다.
  여러 명령으로 읽은 기존 값을 대신 저장하지 않는다. 비교 전후의 값이 같다는 것만으로
  그 사이에 읽은 모든 값이 같은 공고의 것이라고 보장할 수 없기 때문이다.
  표시 여부는 설치된 Selenium의 도구를 사용한다. 좁은 화면에서 잘린 문구도
  기존 `.text`와 같은 방식으로 처리한다.
- 이미지는 `recuritImg`로 구성한 전체 URL을 비교한다. 호스트·경로·쿼리가 일치해야
  하며, 한글 경로 인코딩을 정규화한다. 이미지 다운로드 완료는 기다리지 않는다.
- 클릭 준비·가림·형식·검증·개별 브라우저 오류는 기존 지역별 대기 규칙으로 최대 한 번 재시도한다.
  재시도에서는 카드를 화면 중앙으로 스크롤한다. 가림을 무시하는 클릭은 사용하지 않는다.
- 이전 상세 요청이 남아 있으면 최대 3초 동안 새 요청 없이 기다린다. 계속 진행 중이면
  해당 시도는 증거 확보 실패로 기록하고 새 클릭을 보내지 않는다.
  브라우저 연결 또는 페이지 전체의 기록 장치·상세 모델이 사라지면 실행을 중단한다.
  Python 구현 오류도 개별 공고 오류로 숨기지 않는다.

새 스냅샷으로 저장하는 값의 정리·필터·중복 제거 규칙은 기존 것을 그대로 사용한다.
확인하지 못한 공고는 내보내지 않는다. 수동 공고는 별도로 센다.

## 측정 기록

`RECRU_STATS_PATH`의 JSON 파일에 해당 `RECRU_RUN_ID`의 기록을 남긴다.
로컬 기본 경로는 `recru_stats.json`이며, Actions는 러너 임시 폴더를 사용한다.

- 구간별 대기, 검증, 기존 읽기 비교, 최초 시도와 재시도 시간
- 전체/지역별 대상·확인 성공·최종 실패·완료 여부, 수동 공고·필터 제외·저장 수와 제외 사유
- 클릭 가림, 확인 실패, 형식 차이, 개별 브라우저 오류, 필수 증거 부재, 진단 기록 누락 구분
- 클릭부터 화면 준비까지의 시간: 페이지의 `performance.now()`끼리 계산
- 요청부터 응답 헤더/본문 완료까지의 시간: CDP의 타임스탬프끼리 계산
- 초기 로딩/수집 구간별 상세·목록·기타 사이트·외부 요청 수와 캐시 응답 수,
  HTTP 메서드, 각 분류 및 수집 중 사이트 요청 전체의 움직이는 60초 최대치
- 스크롤 횟수와 전후 목록 수, 카드 단위 추출 대조, 지급 단위 분포, 실제 User-Agent

XHR 전송 호출에 로컬 함수 이름을 붙여 CDP의 initiator stack에 나온 요청 ID와
연결한다. 공고 ID만으로 연결하거나 서로 다른 시계의 시각을 빼지 않는다.
HTTP 요청 내용·헤더·요청 수는 이 연결 과정에서 바꾸지 않는다.
CDP 응답 본문을 조회하지 않는다. 공고 검증에는 페이지의 새 상세 객체와 화면의 대조를 쓴다.
OPTIONS 사전 확인 요청도 요청 수에 포함하고 POST와 구분한다.
클릭 수와 상세 관련 HTTP 요청 수는 다를 수 있다.
요청 종류는 URL로 분류하지만 기록에는 원문 URL, 응답 본문, 공고 내용, 연락처를 넣지 않는다.
시도별 브라우저 진단 조회도 그 시도의 요청만 반환한다. 이전 요청 전체를 매번 전송하지 않는다.
Selenium·urllib3 통신 로그는 WARNING 이상만 출력해, Scrapy가 DEBUG여도 브라우저 응답
전체가 로그에 찍히지 않게 한다. 기존 Scrapy 항목/필터 로그에는 여전히 공고 내용이 있을 수 있다.
표시 여부 판단에 사용하는 내부 파일과의 호환성을 위해 Selenium은 시험한 4.35.0으로 고정한다.

요청 수는 브라우저가 관측한 요청 시작 수다. 캐시·서비스 워커 응답은 따로
표시하며, 이 수치만으로 원 서버의 처리량을 단정하지 않는다. 초기/수집 구간의
경계는 로그를 읽어 비운 시점이다. 늦게 전달된 초기 로딩 로그는 분류가 늦어질 수 있다.
429 또는 503이 사이트 요청에서 관측되면 추가 수집을 중단한다. 이 실행에서 재요청하지
않으므로 서버가 지정한 `Retry-After`보다 일찍 재시도하지 않는다.

시간 합계 중 `first_attempt`/`retry`는 내부의 대기·검증·비교 시간을 포함한다.
이를 세부 시간과 다시 더하면 중복 계산이 된다.

## Actions 반영 조건

`python -m recru_it.validate_run`이 다음을 확인한 뒤에만 결과 파일 복사와 기존
자동 커밋·푸시를 수행한다.

- 이번 실행 ID의 통계와 정상 완료 표시가 존재한다.
- 설정된 17개 지역을 모두 순회했고 각 지역의 대상 수가 성공+실패 수와 맞는다.
- Scrapy 예외와 사이트 429/503이 없고 저장 대상의 텍스트 형식 비교가 통과했다.
  형식이 달라 제외한 공고의 기록은 다른 정상 공고의 반영을 막지 않는다.
- 확인된 공고+수동 공고 수가 최종 저장+필터 제외 수와 맞는다.
- 결과가 기존 13개 문자열 필드의 목록이고 저장 수가 통계와 같으며 50건 이상이다.

위 검증을 통과하지 못하면 원격 저장소에는 마지막 정상 결과가 남는다.
개별 실패율의 숫자 기준은 아직 정하지 않았다. 일부 최종 실패가 있어도 위 검증을
통과하면 확인된 공고를 반영한다. 지역별 비율만으로 자동 중단하지 않는다.
검증을 통과했어도 최종 실패 또는 형식 불일치가 있으면 Actions 경고를 표시한다.
경고에는 공고 수와 시도 수만 담으며 반영 여부는 바꾸지 않는다.
통계만 14일 보관하는 artifact를 남기고, 작업 제한 시간은 45분이다.
수동 Actions 실행에서는 합성 회귀 테스트를 먼저 실행한다. 체크아웃·결과 커밋·푸시는
모두 실행을 지정한 브랜치를 사용하므로, 시험 브랜치를 지정한 실행의 결과가 master로
푸시되지 않는다. 시험 브랜치의 코드 커밋·푸시와 Actions 실행에는 별도 승인이 필요하다.

## 확인 방법

```sh
python -B -m unittest discover -s tests -p 'test_*.py'
```

위 테스트는 합성 화면과 요청을 사용하며 대상 사이트에는 접속하지 않는다.
Chrome이 설치되어 있어야 한다.

```sh
python -B -u tests/live_probe.py
python -B -u tests/run_local_stage1.py
```

두 명령은 각각 실제 공고 8건 확인과 전체 수집을 수행한다. 전체 테스트는 기존
대기 시간과 범위를 유지하고 별도 임시 폴더에 결과·통계·로그를 저장한다.
저장소 결과 파일이나 원격에 반영하지 않는다. 로그와 결과에는 기존 크롤러가
다루는 공고 데이터가 있으므로 진단 artifact에는 통계 파일만 넣는다.

운영에 적용한 뒤 정기 실행 3~5회의 처리량당 시간·응답 지연·실패·지역 완료 상태를
비교한다. 이 단계만으로 2.2초 간격의 성능이나 서버 부담을 검증한 것은 아니다.

참고: [Selenium의 표시 텍스트 처리](https://github.com/SeleniumHQ/selenium/blob/trunk/javascript/atoms/dom.js),
[Chrome DevTools Network 프로토콜](https://chromedevtools.github.io/devtools-protocol/tot/Network/).
